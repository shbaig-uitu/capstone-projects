# UVM Verification Environment

The UVM environment is organized around two transaction paths:

- AXI4-Lite-style VGA register accesses
- Native CPU-side framebuffer accesses through `mem_interconnect`

## Components

- `axi_lite_if.sv` — AXI register interface and observed VGA signals
- `native_mem_if.sv` — native memory bus interface
- `vga_uvm_pkg.sv` — transactions, agents, sequences, scoreboards and functional coverage
- `vga_assertions.sv` — SystemVerilog assertions for VGA timing/address/blanking properties
- `tb_uvm_vga.sv` — UVM testbench top
- `run_uvm.do` — Questa batch regression and UCDB generation

## Cases covered

The UVM sequences exercise CTRL read/write, FB_BASE read/write and alignment/overlap errors, WIDTH/HEIGHT reads, invalid register accesses, display disable/enable, framebuffer byte-lane accesses, framebuffer endpoints and an unmapped address.

## Run

From the repository root:

```bash
export UVM_HOME=/path/to/uvm-1.2
make uvm
```

The runner writes `uvm/reports/uvm_run.log` and, when `vcover` is available, `uvm/reports/coverage.txt`. The UCDB is `uvm/uvm_coverage.ucdb`.

Coverage numbers are not pre-filled; they must be generated by the simulator.
